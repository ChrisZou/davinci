# DaVinci 项目现状与后续发展规划

调研日期：2026-10-29；代码基线：`db995b2`。

目标：先把自己的封面创作流程做好，再逐步对外开放。

## 1. 建议的主线

DaVinci 已经具备相当完整的封面编辑基础。下一阶段最有价值的工作，是让自己每次创作都能更快得到一张愿意发布的封面，并把好用的版式、人物素材和操作习惯留下来，供下次直接复用。

建议围绕一个具体流程推进：

**收藏参考 → 选一个可复用版式 → 换标题和人物 → 生成少量有区别的版本 → 按发布尺寸比较 → 选定、导出 → 留下使用记录。**

近期最重要的产品交付是：**选一个自己常用的模板，换标题和人物后，版式依然成立。**

优先把这件事在自己的真实选题上反复做好。等到连续使用时不再频繁回到其他工具补救，再邀请少量创作者使用相同流程。对外开放的节奏由使用结果决定。

## 2. 项目现在处于什么阶段

### 已有能力足以支撑日常创作

| 模块 | 已核实的现状 | 对下一阶段的意义 |
| --- | --- | --- |
| 编辑器 | 中文文字排版、字体、描边阴影、变形、图片裁剪换图和抠图、形状渐变、图层编组与对齐、多画板 | 主要编辑工具已有基础，可以围绕真实任务补细节 |
| 交互 | 字距已按像素计算并支持输入时预览；画板右键菜单冲突已修复；V 可切换选中图层显隐 | 最近需求集中在操作是否直接、反馈是否及时，这类体验仍值得持续打磨 |
| 收藏与模板 | 图片收藏、来源、作者、点赞数、备注、链接、标签；分层项目可作为模板复制使用 | 信息保存已具备，接下来要提高“收藏之后真正用起来”的比例 |

| 导出 | PNG / JPEG / WebP、多倍率、透明背景、选中图层导出、多画板 ZIP | “多版本输出”的底层能力已在，缺的是更方便的比较与选择 |
| 数据与架构 | 本地 SQLite 保存项目；界面、CLI、HTTP API 使用统一命令；浏览器和服务端共用渲染代码 | 适合继续增量开发，现阶段没有重写架构的必要 |

目前可以判断为：**核心编辑能力已建立，正在从个人编辑工具走向可重复使用的创作流程。** 这不是对商业成熟度或设计质量的认证。

### 本次看到的使用样本

只读检查了当前开发环境的数据：52 个项目，其中 25 个作品、27 个模板；37 个项目有多个画板；素材库有 90 项，配色有 8 套。

27 个模板中，11 个是单张图片，另外 16 个含有顶层文字图层。这说明“收藏参考”和“可编辑复用”同时存在；含文字图层也不等于已经具备自动替换的模板能力。

这些是开发库快照，可能包含测试和历史项目，不代表活跃用户、实际发布量或桌面版全部数据。没有用这些数字推导商业需求。

当前作品的 `templateId` 关联尚未形成可用样本。该字段是近期新增，旧项目和手动复制可能没有记录，因此不能据此判断“模板没人用”。

## 3. 当前最值得解决的五个问题

### 3.1 收藏一张封面，还不能直接复用它的结构

现在导入图片就能进入模板库，但复制一张平面图，不会自动得到可编辑的标题、人物和背景。对自己的创作来说，找到喜欢的参考只是起点，重新搭版仍可能花较多时间。

建议先在现有模板库里区分“参考图”和“可替换模板”，保留统一收藏入口。用筛选和清楚的操作表达区别，避免新增一套重复的资料管理页面。旧数据允许人工纠正分类，不仅凭图层数量自动判断。

先挑出最常用的 5 类版式，整理 5 个真正能复用的模板；经过真实选题验证后再扩到 10 个。质量比数量更重要。

### 3.2 模板缺少明确的替换规则

现有模板是完整项目的副本，普通图层可以编辑，但尚未发现统一的标题、人像等替换字段及约束机制。替换文字后仍可能需要逐个调整字号、换行和位置。

第一版只支持实际需要的字段：主标题、可选副标题、人物图。字段绑定稳定的图层 ID，允许一个字段作用于多个图层，避免依赖容易变化的图层名称。

每个字段可设置少量规则：文字区域、字号范围、最多行数；人物框的裁剪方式和锚点。先用确定的排版规则处理常见替换，超出范围时给出简短状态并允许手动调整。AI 负责更开放的布局变化。

个人风格方案复用现有字体、配色和素材库，只补齐它们之间的组合关系。暂时不建设复杂的品牌管理系统。

### 3.3 多画板已有，但比较和选定版本仍费操作

AI 已能按要求制作多个布局，批量导出也已存在。后续应解决的是：这些版本是否有实质区别，能否快速看清并选定一个。

建议在同一项目内增加轻量的并排比较，支持按实际发布时的缩略图大小查看；可以标记选定画板，导出时优先使用它。原始版本保留，生成操作可以整体撤销。

先固定三种有明确差别的方向，例如“大标题优先”“人物优先”“内容对比”，避免生成大量只换颜色的近似版本。跨尺寸适配先覆盖自己实际使用最多的两个尺寸；宽高变化后要重新检查文字和人物，不能只整体缩放。

### 3.4 已经自动保存，但还缺少跨重启恢复和迁移保障

当前项目会持久化保存，撤销历史保存在内存中，最多 50 步；删除项目使用直接删除。它们与可恢复的版本、误删恢复和整库备份是不同能力。

近期先做小而可靠的恢复能力：重要改动前保留检查点，恢复时生成副本；提供可验证的备份与恢复流程。导出的图片 ZIP 不能代替可编辑项目备份。

可迁移备份至少要包括文档、被引用的素材及必要元数据。字体应有依赖清单和缺失提示；是否随包带字体应依据该字体的分发许可。运行中的 SQLite 备份要保证一致性，不能只复制主数据库文件而忽略 WAL。

回收站和保留策略可随后补齐，不需要先开发完整版本管理界面。

### 3.5 收藏的热度与自己的发布结果还没有关联

已有的来源、作者、点赞数描述的是参考内容，并不能说明自己的封面是否有效。

从下一次创作开始，先用简单记录留下：选题、参考或模板、最终画板、主动操作时间、主要返工原因、是否发布、发布链接。等记录方式稳定后，再决定哪些字段值得放进产品。

平台能提供曝光和点击时才记录点击率，不能用点赞数替代。不同选题、发布时间、账号受众都会影响结果，少量样本只能辅助判断，不作为封面设计带来增长的因果证据。

## 4. 分阶段推进

以下按一名主要开发者借助 AI、具备连续开发时间估算，总体约 8–12 周。它是投入量级，不是交付日期承诺；每一阶段通过实际使用验收后再扩大范围。

| 阶段 | 建议投入 | 核心交付 | 完成条件 |
| --- | --- | --- | --- |
| A：建立可靠的个人基线 | 1–2 周 | 记录真实创作耗时与阻碍；整理 5 个常用版式；补最小检查点及备份恢复；处理最高频交互问题 | 至少完成 5 次真实创作；备份在独立临时目录恢复成功；重启后能恢复一个指定检查点且不覆盖当前作品 |
| B：让模板真正可复用 | 3–4 周 | 参考图与模板筛选；标题、人像替换字段；基础排版约束；复用个人配色、字体与素材；保存模板来源关联 | 在 5 个模板上用短、中、长标题和不同人物测试；常用内容不溢出、不遮住关键主体；连续 5 次真实创作有明确提速 |
| C：更快比较与完成输出 | 2–3 周 | 三种差异化版本；并排与缩略图预览；选定画板；两个常用尺寸适配；继续积累发布记录 | 能从同一选题完成生成、比较、选定和导出；原稿可恢复；输出与画布在字形、裁剪、透明度等关键项一致 |
| D：小范围外部试用 | 2–3 周 | 安装和 AI 环境自检；稳定发布流程；最短上手路径；必要的接口访问限制；邀请 5–10 位同类创作者 | 多数试用者无需开发者实时介入即可完成第一张封面；升级不丢数据；收集到重复出现的需求后再扩大范围 |

若 A 阶段数据显示主要耗时来自找人物或整理参考，就调整 B 阶段内部顺序。阶段安排应服从真实瓶颈。

### A：同时解决效率和信心

选择 10 个固定的代表性任务作为长期验收样本，其中包括中文短标题、长标题、中英混排、描边阴影、不同姿态人物和多画板。优先使用自己的素材。

不要一次把所有历史作品转成模板。先做最常用的 5 个，保留原图对照，记录哪个步骤最容易返工。基础恢复能力完成后，继续投入模板流程，不把这一阶段扩成长期基础设施项目。

### B：把一个流程做顺，再增加模板类型

第一条完整链路：打开常用模板 → 输入标题 → 选择人物 → 预览 → 微调 → 保存作品。

字段设置放在编辑模板时，使用模板时仅呈现需要填写的内容。优先通过布局、选中状态、预览和图标表达，不增加说明性副标题或宣传文案。

测试必须覆盖保存、重开、复制、撤销，以及旧版模板仍可正常编辑。旧项目不应被强制转换为新模板结构。

### C：先做对比，再讨论自动选优

由人判断选题表达和视觉质量。AI 先负责生成有区别、可继续编辑的候选方案，产品提供方便的选择方式。

将“命令成功执行”“画面没有明显错误”“最终愿意采用”分开记录。命令执行成功不能替代视觉质量验收。

跨尺寸优先复用模板约束和已有画板能力。若第二个尺寸的需求很少，先保留手动适配，把时间用于高频版式。

### D：控制试用范围

第一批优先选择和自己创作类型接近、愿意反馈问题的创作者，先覆盖验证充分的系统环境。Windows 已有公开安装包，但 AI CLI 检测、抠图依赖、字体与安装体验需要独立验收。

已有 AI CLI 登录环境的人可以先试用；若目标用户多数没有这种环境，应先验证接入成本和付费意愿，再决定是否提供托管 AI 服务，不能直接把本地个人流程当作大众用户的默认前提。

每轮收集“卡在哪里、返工在哪里、是否再次使用”，优先修复重复出现的问题。暂不据下载次数判断需求成立。

## 5. 自动拆图：保留探索，但设置投入上限

仓库已有 `tools/layerize`，使用 OCR、字体匹配、人物抠图和背景补全，把参考图转换为图层，并支持人工修正。它目前是独立工具链，含 Apple Vision 和额外 Python 依赖，尚不是产品内稳定的一键流程。

建议在 A 或 B 阶段做一次 **2–3 个开发日以内**的验证，先不承诺正式功能：

1. 选 10 张代表性参考封面，包含大字、描边、倾斜文字、人物遮挡和复杂背景。
2. 对比手动重建与拆图后修正的总耗时，包含依赖准备、字体修正和背景修补。
3. 由自己判断能否用于实际创作，不以 OCR 准确率单独决定结果。
4. 若多数样本节省至少约三成总时间，且问题集中在可修正的少数环节，再设计产品入口。
5. 若效果不稳定，先保留工具供熟练使用；优先考虑“提取文字并重建版式”或“只拆标题”，继续积累手工校准模板。

这里的比例是拟定的决策门槛，并非已有测试结果。目标是缩短制作时间，无需追求任意参考图的逐像素还原。

## 6. 用什么判断确实变好

主指标是：**从题目和素材准备好，到选定可发布封面的主动操作时间。** AI 等待时间另记，避免把网络或模型波动混入操作效率。

| 指标 | 记录方式 | 初步目标 |
| --- | --- | --- |
| 制作效率 | 固定代表任务前后对照，并用新选题复核；记录中位时间 | B–C 阶段较基线减少约 30% 的主动操作时间 |
| 完整使用 | 连续真实创作中，有多少张在 DaVinci 内完成最终封面 | 连续 10 次至少 8 次完成；外部生成原始素材不算返工，因编辑缺陷转到其他工具算 |
| 模板复用 | 记录实际采用的模板，以及换标题、人像后的返工项 | 至少 5 个模板被再次用于真实选题，持续减少重复排版 |
| AI 可用性 | 分别记录执行状态、需要返修的原因、最终是否采用 | 先取得真实基线，再决定目标；不直接用评论完成数作为成功率 |
| 可靠性 | 恢复演练、升级检查、固定样本的画布与导出对比 | 验收样本中无数据丢失、缺图、缺字或明显布局偏移 |
| 外部上手 | 记录从安装到第一张导出的阻碍与人工帮助 | 首批试用者多数能独立完成，并观察是否再次使用 |

样本较小时保留具体记录，不做复杂统计看板。这些目标都是建议验收标准，尚未测得。

## 7. 工程上怎样支撑，避免工作失控

### 保留现有架构，扩展统一命令

继续沿用 React / CanvasKit、Go 文档引擎、SQLite 和 Electron。模板替换、版本选择等新操作仍应能由界面与 AI 使用同一套命令完成，批量修改保持一次撤销。

模板字段和规则优先作为兼容旧项目的可选数据；来源关系沿用已有 `templateId`，需要关联参考图和模板版本时再扩展。先设计最小数据结构与迁移测试，不新建第二套编辑文档模型。

前端几个主要文件已经较大，适合在改对应功能时逐步拆出模板替换、画板比较和属性编辑逻辑。不要单为减少行数安排整轮重构。

### 增加对真实流程有价值的验证

把现有检查放进 CI，并补少量完整流程验收：模板复制与替换、重开项目、撤销 AI 批量改动、备份恢复、选择画板导出。建立代表性封面的视觉基准，优先检查字形、换行、裁剪、渐变和透明背景。

保留现有 AI 并发编辑保护。真实模型评估作为单独、可控的检查，记录模型与版本、输入、耗时及采用结果；不默认每次提交都发起真实模型调用。

当前动态命令清单有 55 条，而部分架构说明仍写 52 条。公开文档应以命令注册表生成的 schema 为准，减少手工维护的数量与接口描述。

### 对外扩展前完成具体的发布工作

- 整理当前公开版本之后的改动，完成验收后发布一个可追溯的新版本；记录构建代码版本和安装包版本。
- 继续使用既定 macOS Bundle ID 与签名团队，验证更新原安装位置、重启与数据保留；Windows 单独检查其安装和依赖条件。
- 优先提供版本检查和清楚的更新入口；自动更新是否值得做，由试用维护成本决定。
- 对 AI CLI 的存在、版本、登录状态、自定义安装路径和缺失依赖提供必要自检。错误应直接指出缺少哪一项及下一步操作。
- 普通 HTTP API 目前允许通配跨来源请求，WebSocket 的来源检查直接放行；AI 评论入口已有更严格的限制。扩大试用前统一审查 Origin / Host 规则及本地写入授权，并验证不会破坏 CLI、桌面版和开发环境。此项来自代码检查，本次未做攻击验证。

## 8. 下一轮 10 个工作日建议

这轮只承诺打通一个可验证的小流程，模板字段的完整产品化留到下一阶段。

| 时间 | 工作 | 可检查的产物 |
| --- | --- | --- |
| 第 1–2 天 | 用现有版本完成代表性真实创作，记录主动耗时与返工；选出最常用版式 | 5 次创作记录、按耗时排序的问题清单、固定验收样本 |
| 第 3–5 天 | 做最小备份恢复及指定检查点；复核保存失败和重启后的状态 | 在独立临时目录完成恢复演练，原数据不受影响 |
| 第 6–8 天 | 整理 5 个可复用模板；打通其中一个模板的主标题与人物替换流程 | 同一模板替换短、中、长标题和不同人物，能保存、重开和撤销 |
| 第 9–10 天 | 把该流程用于真实选题；修正最影响使用的问题，确定下一轮范围 | 前后耗时与返工对照，明确继续做哪些模板规则 |

如果前两天发现数据问题，先解决数据可靠性。如果基线表明换标题和人物已经很快，就把后半轮调整为耗时最大的真实步骤，避免为预设方案制造需求。

## 9. 暂不优先投入的方向

| 方向 | 重新考虑的条件 |
| --- | --- |
| 账号、云同步、团队协作、权限 | 多设备或多人需求重复出现，且本地备份与迁移不能满足 |
| 模板商城、付费体系、大规模获客 | 小范围用户持续复用，模板价值及支持成本有证据 |
| 独立移动端、视频编辑、通用设计格式兼容 | 与当前用户的主要创作流程直接相关，且收益超过维护成本 |
| 自动抓取平台表现、增长评分 | 手工记录已稳定使用，确实需要自动化，且数据口径与获取方式可持续 |
| 大规模生图模型接入 | 真实记录显示，缺少原始素材是主要瓶颈，现有外部生成与导入不能满足 |
| 任意封面全自动高保真拆图 | 小样本实验已经证明可以显著节省总制作时间 |

这些方向保留为后续选项，当前不并入 8–12 周的主线承诺。

## 10. 外部产品参考与证据索引

本次只做了相关能力的官方资料核实，没有进行完整市场规模、定价或用户研究。

Canva 的 Autofill 已支持将模板中的元素绑定为数据字段，再通过接口填入内容；其帮助页也列出了 API 和 MCP 的使用方式。对 DaVinci 的启发是把可替换内容明确表达出来，并让本地创作流程使用方便。[官方开发指南](https://www.canva.dev/docs/apps/rest-apis/autofill-guide/) · [官方帮助](https://www.canva.com/help/autofill/)

Adobe Express 的尺寸调整支持预设、自定义尺寸，以及保留原设计再复制调整。对 DaVinci 的启发是保留原稿，让用户能检查并选择适配结果。[官方说明](https://helpx.adobe.com/express/web/arrange-layers-and-pages/change-page-size.html)

由这些能力和当前项目状态推断，DaVinci 更值得验证的优势是：自己的中文封面版式、人物素材和风格能反复复用，局部修改直接可控，AI 与手动编辑衔接自然。这个判断是产品方向建议，尚不是市场验证结论。
